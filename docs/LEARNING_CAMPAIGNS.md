# 측정 기반 모델과 유한 연구 캠페인

Polymer Lab 0.3은 합성 고분자 물성(Tg, 탄성률, 인장강도, 분자량, GPC Mn·Mw·분산도, TGA 열분해 온도)과 같은 단백질 조건에서의 고분자 상호작용(Kd, 접촉/수소결합 수, RMSD) 데이터를 저장하고 비교할 수 있다. 설치 시 실제 측정 학습 데이터나 사전학습 물성 모델은 포함하지 않는다. 새 모델을 만들려면 사용자가 출처와 측정 조건을 검토한 데이터가 필요하다.

## 대리 모델

`SurrogateManager`는 검토 완료(`verified=true`) 실험·문헌 측정만 학습한다. 시뮬레이션값, 데모값, 검토되지 않은 값은 제외한다. 물성별 정규 단위를 사용하며 같은 측정법과 정확히 같은 조건 사전만 함께 학습한다. 서로 다른 반복단위 화학구조/재료 그룹이 최소 8개 필요하고 개인용 GP 계산은 500개 측정까지 제한한다.

입력은 RDKit의 키랄성 포함 128비트 Morgan 지문과 반복단위 기술자 6개다. 선택적으로 완료된 비데모 계산에 직접 연결된 실제 MD 궤적의 피처를 더할 수 있다. MD 피처의 힘장, 전하법, 엔진, 앙상블, 온도, 스텝 수, 프레임 수, 단위, 분석법이 같아야 한다. 구조 생성 전후 미리보기 두 장은 MD 자료로 쓰지 않는다. 누락값을 0으로 채우지 않는다.

모델은 고정 커널의 scikit-learn GaussianProcessRegressor 기준 모델이다. 동일 재료 ID 또는 동일 정규화 반복단위 구조를 공유하는 관측은 하나의 연결 그룹으로 묶어 GroupKFold를 수행한다. 따라서 이름을 바꾸거나 사슬 길이가 다른 같은 반복단위 복제본이 학습/검증 양쪽에 들어가지 않는다. 교차검증 MAE/RMSE와 각 분할의 재료·화학구조 목록을 저장한다. 모델 파일은 실행 코드가 아닌 해시가 붙은 JSON 학습 스냅샷이며 예측 시 다시 적합한다.

단백질 관련 목표는 하나의 단백질 조건에서만 학습한다. 업로드 PDB의 해시가 있으면 이를 우선 사용해 폼의 기본 accession 때문에 서로 다른 단백질이 합쳐지지 않게 한다. 없으면 명시한 protein_id, 서열 또는 accession을 쓴다. 예측에도 정확한 `protein_context`가 필요하다. 다른 단백질로의 일반화나 결합 자유에너지는 구현하지 않았다.

반환하는 GP 표준편차는 보정된 신뢰구간이 아니다. 지문 유사도와 기술자 범위 이탈을 알려주지만 적용 가능 영역을 검증했다는 뜻은 아니다. 반복단위 기술자는 분자량 분포, 공중합체 서열, 입체규칙성의 전체 효과를 표현하지 않는다. 짧은 MD 피처를 붙여도 실제 multi-fidelity 모델 또는 높은 물성 정확도가 자동으로 성립하지 않는다. 모델 응답의 `is_multifidelity`는 항상 false다.

## 캠페인

캠페인은 사용자가 명시한 최대 200개의 유효한 JobConfig 후보에서 선택한다. 실행 예산은 최대 50개, 한 배치는 최대 10개다. 생성만으로 계산을 시작하지 않는다. 사용자가 한 배치 실행 또는 자동 시작을 선택해야 한다. 자동 모드는 한 배치가 끝나고 결과가 색인된 후 다음 배치를 선택하며 예산을 넘지 않는다. 종료/재시작 뒤 자동 실행은 일시 정지되어 수동 재개가 필요하다.

한 캠페인에서는 경로, 엔진, 힘장 관련 설정, 스텝, 시드, 타임스텝, 단백질 입력을 고정한다. 화학구조, 사슬 길이, 사슬 수, 온도, 박스 크기를 비교할 수 있다. 일반 CG 모델에서는 SMILES를 화학 표현으로 쓰지 않으며, 실제 재료 실험 물성 목표와 연결할 수 없다. 목적함수는 단일 지표의 최소화/최대화다. 다목적 최적화 및 제약 기반 설계는 이번 버전에 포함하지 않는다.

기본 sklearn 추천기는 초기에는 시드가 고정된 기술자 공간의 maximin 다양성 표집을 쓴다. 호환되는 관측이 5개 쌓이면 GP expected improvement로 다음 후보를 고른다. BayBE가 설치되어 있으면 실제 BayBE의 FPSRecommender와 5개 관측 이후 BotorchRecommender를 사용한다. 화학 후보는 RDKit 숫자 기술자를 전달하는 유한 검색공간이며 BayBE의 별도 chemistry extras에 의존하지 않는다.

재료명이 달라도 실행 입력이 같으면 중복 후보로 합친다. 제출 전 예약을 디스크에 남겨 중간 종료 후 같은 후보를 조용히 다시 실행하지 않는다. 실패·취소·누락된 후보는 정확한 해시만 재추천에서 제외한다. 근처 조건까지 자동으로 위험 영역이라고 추정하는 학습은 구현하지 않았다. 계산 실패를 성공 목표값이나 0으로 치환하지 않는다.

실험값을 목표로 삼는 캠페인은 해당 작업과 연결된 검토 완료 실험/문헌값, 동일 측정법·조건을 기다린다. 같은 조건의 반복 측정은 산술평균과 원본 measurement ID를 기록한다. 피처 단위 또는 분석법이 서로 다르면 추천을 중단한다.

## 검증과 재현

`tests/test_learning_campaigns.py`는 임시 데이터베이스의 명백한 합성 테스트 자료로 그룹 분리, 데이터 출처 제외, 조건/단위 거부, 단백질 문맥, 실제 MD 여부, 해시 변조 탐지, 예산·중복·실패·재시작을 검사한다. 실제 NumPy 작업 2개가 자동 캠페인을 통해 실행되고 색인되는 경로와 설치된 BayBE 초기/관측 후 추천도 실행한다. 이 검사는 소프트웨어 동작 검증이며 Tg·탄성률·결합 예측의 실험 정확도 검증은 아니다.

관련 구현 근거는 `evidence/extensions/audit.json`의 고정 커밋·원본 파일 해시·API 위치와 각 REA 실행 기록에 있다. REA source inventory가 과학적 정확성을 증명하지는 않는다.
