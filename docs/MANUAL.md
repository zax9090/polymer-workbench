# Polymer Lab 사용설명서

Polymer Lab은 고분자·단백질 구조 생성, 분자 시뮬레이션, 연구 데이터 관리, 실험계획법(DOE)과 조건 최적화를 한곳에서 수행하는 개인 연구 도구입니다. 계산 결과와 입력·로그·출처를 함께 보관합니다. Materials Studio와 Minitab에서 쓰이는 일부 방법을 공개 문헌과 오픈소스로 구현하며, 두 제품의 전체 기능이나 결과와의 일치를 보장하지 않습니다.

사용 안내는 이 문서 하나에서 관리합니다. 앱의 **설명서**를 누르면 같은 문서를 읽을 수 있습니다. 화면에는 입력 항목, 실행 상태와 결과 해석에 필요한 경고를 남깁니다.

## 설치와 실행

### 소스에서 실행

Linux와 Python 3.12 이상을 사용합니다. Rust 계산 기능에는 Rust의 `cargo`가 필요합니다. [rustup](https://rustup.rs/)으로 설치한 뒤 새 터미널에서 `cargo --version`을 확인하세요. 다운로드를 포함한 최초 설치는 시간이 걸릴 수 있습니다.

저장소 폴더에서 실행합니다.

```sh
bash setup.sh
./start.sh
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다. 포트가 사용 중이면 `POLYMER_PORT=8766 ./start.sh`로 바꿀 수 있습니다. 서버는 기본적으로 이 컴퓨터에서만 접속합니다.

`setup.sh`는 프로젝트 전용 `.venv`에 고정된 의존성을 설치하고, `cargo`가 있으면 Rust 커널도 빌드합니다. Rust를 나중에 설치했거나 Rust 코드를 바꾼 경우 다음 명령으로 다시 설치하고 앱을 재시작하세요.

```sh
.venv/bin/python -m pip install ./native
```

RDF·MSD·자유 부피·Widom과 DOE 계산에는 이 커널이 필요합니다. REA 감사에 쓰는 Node.js는 일상적인 앱 실행에는 필요하지 않습니다. 외부 계산 엔진은 **계산 엔진** 화면에서 설치 여부를 확인합니다. 모든 선택 엔진이 없더라도 설치된 경로와 데이터 관리 기능을 사용할 수 있습니다.

### 데스크톱에서 실행

설치된 Linux 배포본은 앱 메뉴의 **Polymer Lab 고분자 연구실** 또는 `~/.local/bin/polymer-lab`으로 실행합니다. 배포본에는 Python 실행 환경이 포함됩니다. 압축 배포본에서는 압축을 푼 폴더의 `./launch.sh`를 실행하고, `_internal` 폴더를 함께 보관하세요. `./install-desktop.sh`는 사용자 계정에 바로가기를 설치합니다.

소스에서 데스크톱 창을 열려면 다음을 실행합니다.

```sh
.venv/bin/python -m pip install -r requirements.desktop.lock.txt
./launch-desktop.sh
```

데스크톱 앱을 닫으면 앱이 관리하는 진행 중 계산도 중단되고 기록은 보존됩니다. 이전에 만든 배포본에는 최신 소스의 기능이 없을 수 있습니다. 최신 배포본이 필요하면 `.venv/bin/python scripts/build_desktop.py --deb`로 다시 빌드합니다. 현재 배포 대상은 Linux x86_64이며, 빌드 환경보다 오래된 glibc나 다른 운영체제에서 실행을 보장하지 않습니다.

작은 화면에서는 설정 패널을 접고 결과를 볼 수 있습니다. 넓은 표는 표 안에서 가로로 이동합니다. 설명서는 별도 탭에서 열리므로 입력 중인 화면을 유지할 수 있습니다.

일반 계산은 **경로 선택 → 설정 입력 → 실행 → 상태·로그 확인 → 결과 저장** 순서입니다. 같은 설정으로 다시 실행해도 새 작업이 생깁니다. 재실행은 중단 지점부터 이어지는 체크포인트 재개와 다릅니다.

| 상태 | 의미와 다음 행동 |
|---|---|
| `queued` / `running` | 대기 또는 실행 중. 로그와 현재 단계를 확인합니다. |
| `completed` | 선택한 경로가 끝까지 실행됨. 수렴·단위·경고를 따로 확인합니다. |
| `prepared` | 입력 파일을 만들었음. 실제 계산에 필요한 엔진과 다음 단계를 확인합니다. |
| `blocked` | 엔진이나 필요한 입력이 없음. 표시한 원인을 해결한 뒤 새로 실행합니다. |
| `failed` | 계산 오류. 마지막 로그와 입력·엔진 버전을 함께 확인합니다. |
| `cancelled` / `interrupted` | 사용자 취소 또는 앱·프로세스 종료. 남아 있는 파일과 로그를 확인합니다. |

작업에는 설정, 로그, 실행 환경, 구조·궤적, 결과 JSON, 산출물 목록과 해시가 저장됩니다. 경로에 따라 파일 종류는 다릅니다. 작업이 끝난 뒤 ZIP을 저장하세요. `completed`는 과학적 타당성을 인정한 표시가 아닙니다.

## 실험 설계와 최적화

**실험 설계·최적화**에서 설계표를 만들고, 측정값 분석 → 모델 비교 → 조건 추천 → 확인 실험으로 연구를 이어갑니다. Rust가 설계, 회귀·분산분석, 잔차 진단, 예측구간과 범위 내 최적화를 계산합니다. 수치형 공정 인자의 DOE, 성분 비율의 합이 1인 혼합물 실험, 여러 반응을 함께 맞추는 만족도 최적화를 다룹니다.

### 실험표 만들기

1. 인자마다 이름·하한·상한을 입력합니다. 예를 들어 `temperature_C`, `catalyst_pct`처럼 단위를 이름에 넣으면 CSV에서도 구분하기 쉽습니다. 모든 인자는 수치형이며 하한은 상한보다 작아야 합니다.
2. 설계 방법을 고릅니다. **2수준 완전 요인 설계**는 2~6개 인자의 주효과와 2인자 상호작용을 살펴볼 때 사용합니다. **중심 합성 설계 · 면 중심**은 2~4개 인자에서 곡률을 포함한 2차 반응표면을 적합할 때 사용합니다. 면 중심 축점은 입력 범위 안에 있습니다.
3. **반복·중심점·실행 순서**에서 반복 수, 중심점 수, 난수 시드를 설정합니다. 반복은 1~10회, 중심점은 반복마다 0~20개이며 중심 합성 설계에는 중심점이 1개 이상 필요합니다. 전체 실험 수는 1,000회를 넘을 수 없습니다. 반복 실험은 독립적으로 수행하며 같은 시료의 기기 판독을 복사해 대체하지 않습니다. 같은 설정과 시드로 같은 무작위 실행 순서를 재현할 수 있습니다.
4. **설계 생성**을 누르고 **CSV 저장**으로 실험표를 받습니다. 표의 `run_order` 순서를 사용하되 실제 실험에 제약이 있으면 따로 기록하세요. 현재 설계에는 블록·범주형 인자·제약식이 포함되지 않습니다.

CSV에는 `run_order`, `point_type`, 각 인자 열과 비어 있는 `response` 열이 있습니다. `point_type`은 요인점·중심점·축점을 구분하는 표시입니다. 인자 이름에 `run_order`, `point_type`, `response`, `Intercept` 또는 `:`·`^` 문자를 사용하지 마세요.

### 측정값으로 분석

1. 설계표의 모든 `response` 칸에 측정값을 채웁니다. 한 열에는 같은 단위·방법의 결과를 넣습니다. 실험을 못 한 칸을 0으로 대신 채우지 마세요.
2. **실험 결과 CSV**에서 파일을 고르거나 붙여 넣습니다. UTF-8 CSV, 웹 화면 기준 최대 1 MB를 받습니다. 반응값 열 이름은 바꿀 수 있으며 **반응값 열**에서 선택합니다.
3. 화면의 인자 이름·범위가 그 CSV를 만든 설정과 같은지 확인합니다. 저장한 설계를 열고 **이 설계 CSV로 측정값 입력**을 누르면 해당 인자 설정과 설계 CSV를 다시 가져옵니다. 기존 CSV를 따로 가져올 때도 인자 목록을 맞춰야 합니다. 선택한 인자와 반응값에 빈칸·숫자가 아닌 값·무한대가 있거나, 인자 값이 지정 범위를 벗어나면 분석을 중단합니다.
4. **주효과**, **주효과 + 2인자 상호작용**, **2차 반응표면** 중 모델을 고릅니다. 2차 모델은 2~4개 인자에서 사용합니다. 2수준 요인점과 중심점만으로는 여러 인자의 제곱항을 따로 추정할 수 없으므로 중심 합성 설계를 사용하세요.
5. **최대화**, **최소화**, **목표값에 맞추기**를 고릅니다. 목표값을 고르면 반응값과 같은 단위의 숫자를 입력하고 **분석·최적화**를 누릅니다.

관측 수는 모델 계수 수보다 많아야 하고 각 항을 독립적으로 추정할 수 있어야 합니다. 인자가 k개이면 절편을 포함한 계수 수는 주효과 `1+k`, 상호작용 `1+k+k(k−1)/2`, 2차 모델 `1+2k+k(k−1)/2`입니다. 상호작용 모델에는 모든 2인자 곱만 포함하며 3인자 이상의 곱은 포함하지 않습니다. 단순히 행을 복제한다고 부족한 설계가 해결되지는 않습니다.

### 결과 읽기와 확인 실험

결과에는 R², 조정 R², 예측 R², RMSE, 분산분석표(ANOVA), 계수의 p값과 95% 신뢰구간이 포함됩니다. 계수는 각 인자의 하한을 −1, 상한을 +1로 바꾼 척도에 대한 값입니다. 서로 다른 단위의 원래 인자에 그대로 곱하지 마세요.

**모델 비교**에서 같은 관측값에 대한 주효과·상호작용·2차 모델을 나란히 봅니다. 예측 R²는 한 행씩 제외해 예측한 오차(PRESS)로 계산하며 음수가 될 수도 있습니다. 추정할 수 없는 모델은 이유와 함께 표시합니다. 모델을 선택해도 바로 재분석하지 않으므로 입력을 확인한 뒤 **분석·최적화**를 누르세요.

분산분석표는 회귀와 잔차를 나누며, 같은 인자 조건의 독립 반복이 있으면 잔차를 **순수 오차**와 **적합 결여**로 나눕니다. 적합 결여 p값이 작으면 현재 모델이 반응 형태를 충분히 설명하지 못할 수 있습니다. 반복점이 없거나 필요한 자유도가 부족하면 해당 검정을 표시하지 않습니다. 잔차 그래프와 표준화 잔차·레버리지·Cook 거리에서 표시한 행은 검토 대상으로만 취급하며 자동 삭제하지 않습니다. CSV의 행 순서를 시간 순서로 해석하려면 실제 실행 순서대로 입력해야 합니다.

**표준화 효과 파레토 차트**는 상수항을 뺀 각 항의 |t|를 큰 순서로 보여 주고, 잔차 자유도의 5% 양측 t 기준선을 넘는 막대를 밝게 표시합니다. 효과의 크기 순서일 뿐 원인을 뜻하지 않으며, 주효과를 뺀 채 상호작용만 남기는 식의 판단은 계층 구조와 잔차를 함께 보고 하세요. **반응표면 색 지도**는 첫 두 인자 평면에서 모델 예측값을 그리며, 인자가 셋 이상이면 나머지 인자를 추천 조건 값에 고정합니다. 밝을수록 예측값이 크고, 고리는 추천 조건입니다. **인자별 예측 프로파일**은 한 인자만 범위 전체로 바꾸고 나머지는 추천 조건 값에 둔 예측 곡선이며, 세로축을 모든 인자가 함께 씁니다. 색 지도와 프로파일은 모두 모델 예측값이며 관측값이 아닙니다.

추천 조건은 지정한 인자 범위 안에서 여러 시작점을 사용하는 탐색으로 구한 **모델의 추천값**입니다. 전역 최적점이나 실제 실험의 최적 조건을 보장하지 않습니다. 반응표면이 잘 맞지 않거나 잔차에 곡선·분산 변화·시간 순서가 보이면 모델과 실험 설계를 다시 검토하세요. 신뢰구간은 회귀의 오차 가정에 따르며 공정 변동 전체를 나타내지 않습니다.

추천 조건에는 평균 반응의 95% 신뢰구간과 새 관측값 한 개의 95% 예측구간이 표시됩니다. 두 구간은 실험 범위 안에서도 모델과 독립·정규·등분산 오차 가정에 의존하며, 같은 데이터로 최적 조건을 선택한 영향까지 보정하지 않습니다. 잔차가 수치 정밀도 수준인 정확 적합에서는 폭이 거의 0일 수 있으므로 실제 반복 정밀도로 해석하지 마세요.

화면의 다음 단계에서 모델 검토 사항을 확인하고, **확인 실험표**를 내려받아 추천 조건에서 독립된 세 번의 실험을 계획합니다. 반응값은 빈칸으로 남겨 두며 실제 측정 후 채웁니다. 확인 실험이나 벌크 계산은 자동 실행되지 않습니다. DOE 결과는 검토된 측정값으로 자동 등록되지 않으며, 학습용 데이터에 쓰려면 출처·단위·조건과 함께 **실험 데이터**에서 등록하고 검토합니다.

설계와 분석은 실행할 때마다 고유 기록으로 저장됩니다. **저장한 설계·분석**에서 다시 열고 원본 CSV·결과 JSON을 받을 수 있습니다. JSON에는 입력 해시와 실행 설정이 포함되며 Google Drive 전체 백업에도 들어갑니다.

### 혼합물 실험

수지·경화제·첨가제처럼 성분 비율의 합이 1인 배합은 **혼합물 설계**를 씁니다. 성분을 하나 늘리면 다른 성분이 줄기 때문에, 공정 인자처럼 각 성분의 효과를 따로 떼어 볼 수 없습니다.

1. 성분마다 이름과 비율 하한·상한(0~1)을 입력합니다. 하한의 합은 1보다 작고 상한의 합은 1보다 커야 합니다.
2. 설계 방법을 고릅니다.
   - **심플렉스 격자 {q, m}:** 각 성분 비율이 0, 1/m, …, 1인 모든 배합입니다(m = 2면 꼭짓점과 이원 배합).
   - **심플렉스 중심:** 모든 성분 조합의 중심(꼭짓점, 이원 1:1, 삼원 1:1:1 …)입니다.
   - **꼭짓점 설계:** 상한이 배합 영역을 자를 때 씁니다. 영역의 꼭짓점을 쓰고, 차수 2면 모서리 중점도 넣습니다.
   - **전체 중심점**과 **축 점검 배합**(중심과 각 꼭짓점의 중간)을 더하면 2차 모델을 점검할 자유도가 생깁니다.
3. 하한이 있으면 L-유사성분 z = (x − L)/(1 − ΣL)으로 설계하고 적합합니다. 계수는 유사성분 기준입니다.
4. 측정값을 채운 CSV로 **혼합물 측정값 분석**을 실행합니다. 각 행의 성분 비율 합이 1(±10⁻⁶)이 아니거나 범위를 벗어나면 중단합니다.
5. Scheffé **1차·2차·특수 3차** 모델 중 고릅니다. 절편이 없는 모델입니다. 1차 계수는 순수 (유사)성분의 예측 반응이라 0인지 검정하지 않습니다. 2차 계수(A:B)는 두 성분 사이의 상승·상쇄 효과입니다.
6. 결과에는 모델 비교, 분산분석, 성분 합이 1인 범위 안의 추천 배합과 95% 예측구간이 나옵니다. 3성분이면 적합한 모델의 **삼각 색 지도**가 함께 그려집니다. 색 지도는 예측값이며 관측값이 아닙니다.

### 다중 반응 만족도 최적화

강도는 높이고 비용과 점도는 낮추는 것처럼 반응이 여럿이면 **다중 반응 만족도 최적화**를 씁니다(Derringer–Suich 1980).

1. 설계 변수로 위의 혼합물 성분 또는 공정 인자를 고릅니다.
2. 변수 열과 반응 열이 모두 있는 CSV를 넣습니다.
3. 반응마다 모델과 목표를 정합니다.
   - **최대화:** 하한 이하이면 d = 0, 목표값 이상이면 d = 1, 사이는 비례합니다.
   - **최소화:** 반대 방향입니다.
   - **목표값:** 하한·상한 밖이면 0, 목표값에서 1입니다.
   - **중요도(0.1~10):** 종합 만족도 D = (Π dᵢ^중요도)^(1/Σ중요도)에서 각 반응의 무게입니다.
4. 결과는 D가 가장 큰 후보 조건, 반응마다 예측값·95% 예측구간·개별 d, 관측한 실험 가운데 D가 가장 높은 행입니다.

범위와 중요도는 연구자가 정하는 기준입니다. D 값 자체에는 물리적 의미가 없고, 같은 데이터라도 기준을 바꾸면 최적 후보가 바뀝니다. 반응마다 따로 맞춘 모델을 쓰므로 반응 사이 상관과 D의 불확실성은 반영하지 않습니다. 후보는 확인 실험으로 검증하세요.

### 처음 연습할 때

실제 실험 전에는 합성 데이터로 흐름을 확인할 수 있습니다. 인자 `x1`, `x2`를 각각 −1~1로 두고, 중심 합성 설계·중심점 3개·반복 1회로 생성합니다. CSV의 각 `response`를 `10 + 4*x1 − 2*x2 − 3*x1² − 2*x2²`로 채우고 2차 모델·최대화로 분석합니다. 이 합성 함수의 최댓값 조건은 `x1=2/3`, `x2=−1/2`입니다. 실제로 측정한 데이터가 아니므로 연구 측정값으로 등록하지 마세요.

## 공정 데이터 분석

왼쪽 메뉴의 **공정 데이터 분석**은 반도체·고분자 공정의 표 데이터(로트·웨이퍼·측정 위치별 두께, 장비별 불량 수, 불량 분류·가상계측 모델의 예측 등)를 CSV 하나로 읽어 분석합니다. 분석에 쓰는 열 이름은 직접 지정합니다. 선택한 열에 빈 값이나 숫자가 아닌 값이 있으면 그 행을 자동으로 빼지 않고 CSV 행 번호와 함께 오류를 냅니다. 결과는 저장하지 않으며 측정값으로 등록되지 않습니다. 필요한 결과는 **결과 JSON 저장**으로 보관하세요. **예제 데이터 넣기**는 합성 데이터이며 실제 측정값이 아닙니다.

CSV는 20 MB·20만 행 이하이고, 한 행이 무엇을 뜻하는지(예: 웨이퍼 한 장의 한 측정 위치) 먼저 정해 두어야 합니다. 시간 순서가 중요한 분석은 **시간 순서 열**(숫자 또는 `2026-10-22T10:05:00` 같은 ISO-8601 시각)을 지정하세요. 지정하지 않으면 파일의 행 순서를 시간 순서로 봅니다.

### 데이터 사전 · 연결 키 점검

연결 키를 상위에서 하위 순서로 적습니다(예: `lot_id, wafer_id, site_id`). 키 값이 빈 행, 같은 키가 여러 번 나온 행, 측정값이 숫자가 아닌 행을 CSV 행 번호와 함께 보여줍니다. 단계마다 고유 값 수와 상위 하나당 하위 수를 표시하고, 하위 키가 상위 없이도 고유한지 알려줍니다. 웨이퍼 번호 1~25를 로트마다 다시 쓰는 경우처럼 고유하지 않으면, 다른 표와 연결할 때 반드시 상위 키와 함께 연결해야 합니다. 단위를 적지 않으면 경고합니다.

### 관리도

부분군 열이 없으면 **개별값–이동범위(I-MR)** 관리도, 있으면 **X̄–S** 관리도를 그립니다. 한계는 중심선 ± 3σ이며, σ는 I-MR에서 평균 이동범위/d₂(2), X̄–S에서 부분군 표준편차 평균/c₄(n)로 추정합니다. X̄–S는 모든 부분군 크기가 같아야 합니다. 신호 규칙은 다음 다섯 가지이며, 규칙을 완성하는 점에 표시합니다.

| 규칙 | 뜻 |
|---|---|
| 3σ 밖 1점 | 한 점이 관리 한계를 벗어남 |
| 연속 3점 중 2점이 2σ 밖 | 같은 쪽 2σ 밖이 3점 중 2점 |
| 연속 5점 중 4점이 1σ 밖 | 같은 쪽 1σ 밖이 5점 중 4점 |
| 연속 8점이 중심선 한쪽 | 평균이 한쪽으로 옮겨 감 |
| 연속 6점 상승·하강 | 꾸준한 증가·감소 경향 |

**기준 구간 점 수**를 비우면 한계를 같은 데이터로 계산합니다(사후 분석). 안정된 앞부분 점 수를 지정하면 그 구간으로 한계를 고정하고 뒤의 점을 판정합니다. 부분군 평균의 흩어짐이 부분군 안의 변동으로 예상되는 것보다 2배 이상 크면 경고합니다. 회차 간 변동이 큰 공정(예: 산화막 두께의 로 회차)에서는 X̄ 한계가 대부분의 점을 벗어나게 그려지므로, 먼저 분산 성분을 확인하세요. 신호는 생산·점검 기록을 확인할 점을 가리킬 뿐 원인을 알려주지 않습니다.

### 공정 능력

규격 하한(LSL)과 상한(USL) 중 하나 이상을 입력합니다. **Cp·Cpk**는 단기 변동(부분군 안 또는 이동범위로 추정한 σ)으로, **Pp·Ppk**는 전체 표본 표준편차로 계산합니다. 두 값의 차이가 크면 회차 간 변동이나 이동(drift)이 있다는 뜻입니다. 정규분포를 가정한 예상 규격 밖 ppm, 실제 규격 밖 개수, Ppk의 95% 근사 구간(Bissell), Shapiro–Wilk 정규성 검정 p값을 함께 보여줍니다. 공정이 안정적이지 않거나 정규성이 기각되면 지수와 ppm을 그대로 믿지 마세요. 측정값은 10개 이상 필요합니다.

### 분산 성분

계층 인자를 상위에서 하위 순서로 적습니다(예: `run, zone`). 최하위 인자 안의 반복(예: 구역마다 웨이퍼 2장)이 잔차가 됩니다. 각 단계의 관측 수가 같은 **균형 설계**만 지원하며, 다르면 오류를 냅니다. 내포(nested) 확률효과 분산분석의 기대 평균제곱으로 분산 성분을 계산하고, 각 단계는 바로 아래 단계의 평균제곱으로 F 검정합니다. 추정값이 음수이면 0으로 표시하고 경고합니다. 상위 그룹 수가 적으면(예: 회차 21개) 그 성분은 불확실하므로 자유도를 함께 보세요. 변동의 대부분이 어느 단계에서 생기는지 알면 어떤 기록(회차별 레시피, 구역별 온도, 웨이퍼 위치)을 더 볼지 정할 수 있습니다.

### 층별 불량률 비교

장비처럼 비교할 **그룹** 열과 제품·난이도처럼 결과에 영향을 주는 **층** 열을 지정하고, 불량 수와 검사 수 열을 함께 주거나 0/1 결과 열 하나를 줍니다. 그룹별 전체 불량률, 층별 불량률과 그룹 안 구성비, 전체 층 구성으로 맞춘 **표준화 불량률**을 보여줍니다. 기준 그룹(비우면 이름순 첫 그룹)과 각 그룹을 Mantel–Haenszel 위험비·오즈비(95% 구간), CMH 검정, Breslow–Day 동질성 검정으로 비교합니다. 전체 비교와 모든 층의 비교 방향이 반대이면 **심슨 역설**로 표시합니다. 예를 들어 장비 B의 전체 불량률이 높아도 B가 고난도 제품을 주로 검사했다면, 같은 제품끼리 비교한 B의 불량률은 더 낮을 수 있습니다. 동질성 검정이 기각되면 하나로 합친 값 대신 층별 결과를 보고하세요. 기록된 층 외의 원재료 로트·기간·점검·재작업 차이는 이 분석으로 제거되지 않습니다.

### 불량 판정 평가

불량 분류 모델의 **정답 열**(불량을 뜻하는 값, 기본 `1`)과 **점수 열**(클수록 불량 가능성이 큼)을 지정합니다. **판정 기준**마다 `점수 ≥ 기준`이면 경고로 보고 잡은 불량·놓침·오탐, 정확도, 불량 검출률(재현율), 정밀도, 경고 비율을 보여줍니다. 함께 표시되는 **모두 정상 판정** 행은 아무것도 경고하지 않는 기준선입니다. 불량이 드물면 이 기준선도 정확도가 높으므로(예: 1,567개 중 불량 104개이면 93.36%), 정확도만으로 모델을 판단하지 마세요. ROC AUC와 평균 정밀도(AP)는 기준과 무관한 순위 성능이며, AP의 무작위 수준은 불량 비율입니다.

**놓침 1건 비용**과 **오탐 1건 비용**을 함께 넣으면 기준별 비용과, 가능한 모든 기준 중 비용이 가장 작은 기준을 보여줍니다. 비용 가정이 바뀌면 고를 기준도 달라집니다. 이 최소 비용 기준은 같은 데이터에서 고른 것이라 낙관적이므로, 검증용 로트에서 고르고 이후 로트에서 다시 확인하세요. 점수 0.7은 보정하지 않은 모델에서 불량 확률 70%를 뜻하지 않습니다.

### 가상계측 오차

**실측값 열**과 **예측값 열**로 전체 MAE·RMSE·평균 편향(예측 − 실측)·R²를 계산합니다. 규격 한계와 **경계 구간 폭**을 넣으면 실측값이 한계 ± 폭 안에 있는 행만의 MAE를 따로 보여줍니다. 합격·불합격이 갈리는 곳은 경계 근처이므로, 전체 MAE가 작아도 경계 구간 오차가 크면 판정에 쓰기 어렵습니다. 예측값으로 판정했을 때 놓친 규격 밖 행과 오탐도 함께 셉니다. 평가에 쓰는 행은 모델 학습에 쓰지 않은 행이어야 합니다.

### 검증 분할 비교

같은 기본 모델(중앙값 대치 + 표준화 + 클래스 균형 로지스틱 회귀, 수치 예측은 릿지 회귀)을 세 가지 방식으로 나눠 평가합니다.

| 분할 | 뜻 |
|---|---|
| 무작위 | 행을 섞어 나눔. 같은 로트·기간의 행이 학습과 평가에 함께 들어갈 수 있음 |
| 로트(그룹) 분리 | 같은 로트는 한쪽에만 들어감. 처음 보는 로트에 대한 성능 |
| 시간 순서 | 과거로 학습하고 다음 구간을 평가. 실제 운영과 가장 비슷함 |

무작위 분할이 로트·시간 분할보다 뚜렷하게 좋으면(AUC 0.05 이상, 또는 MAE가 25% 이상 작음) **누수 의심**으로 표시합니다. 이때는 무작위 분할 결과가 아니라 로트·시간 분할 결과를 보고하세요. 입력 변수에 빈 값이 있으면 오류를 내며, **빈 입력값을 학습 구간 중앙값으로 채우기**를 직접 선택해야 채웁니다. 이 분석은 분할 방식을 비교하는 것이지 모델의 최고 성능을 찾는 것이 아닙니다.

## 연결된 벌크 연구 흐름

**실험 설계·최적화 → 벌크용 인자 설정**으로 온도와 초기 패킹 밀도의 면 중심 설계를 준비합니다. 범위를 확인하고 설계를 생성한 뒤 **벌크 계산에 연결**을 누릅니다. 저장만으로 계산이 시작되지는 않습니다.

현재 연결 경로는 **전원자 벌크 / GAFF2 / 자체 셀 빌더**입니다. 이 경로에서만 초기 패킹 밀도가 실제 사슬 성장 입력에 적용됩니다. RadonPy 기본 패킹과 PCFF의 고정 초기 밀도를 변경된 인자로 취급하지 않습니다. 초기 패킹 밀도는 계산 준비 조건이며 최종 밀도나 소재 조성이 아닙니다.

1. 인자 두 개를 **온도(K)**와 **초기 패킹 밀도(g/cm³)**에 각각 연결합니다. 범위는 온도 100~500 K, 초기 패킹 밀도 0.3~1.2 g/cm³ 안에 있어야 합니다. 고분자·사슬 수·힘장·전하·프로토콜 길이는 흐름 안에서 고정됩니다. 설계의 각 행은 별도 시드를 사용합니다.
2. 대표 반응값을 고르고, 필요하면 **함께 수집할 반응값**을 더 고릅니다. 각 행을 분석할 때 고른 값을 모두 기록합니다.
   - **최종 구조 밀도**, **탐침 접근 가능 부피 비율**: 최종 구조의 자유 부피 분석에서 얻습니다. 탐침 기본값은 1 Å, 격자 간격은 0.25 Å이며 h·2h 격자를 씁니다. 최종 구조 밀도는 NPT 궤적 평균 밀도와 다릅니다.
   - **NPT 평균 밀도**, **체적 탄성률**(부피 요동), **부피 팽창 계수**: 계산의 NPT 표본 구간 평균(`bulk_complete.json`)에서 얻습니다. RadonPy의 수렴 판정이 함께 기록되며, 수렴하지 않았으면 표에 "NPT 미수렴"이 붙습니다. 짧은 MD의 탄성률·팽창 계수는 수렴값이 아닙니다.
   - 최적화할 때 원본 파일의 해시와 값을 다시 확인합니다. 분석 뒤 결과 파일이 바뀌면 최적화를 거부합니다.
3. 실행할 행을 선택하고 **실행 미리보기 → 설정을 확인하고 계산 실행**을 누릅니다. MD 계산은 한 번에 하나씩 실행합니다. 구조 분석과 통계 계산은 다른 실행 줄을 쓰므로 MD가 도는 동안에도 실행됩니다. 전체 설계는 최대 50행, 예산에는 새 계산·실패 재시도·추천 확인 계산이 포함됩니다. 중복 제출은 같은 작업을 다시 실행하지 않습니다.
4. 계산이 완료되면 선택한 행의 **분석·반응값 수집**을 누릅니다. 실제 완료 작업의 설정·시드가 일치하면 **완료된 기존 작업 연결**도 가능합니다. 한 작업을 두 반복 행에 중복 연결할 수 없습니다.
5. 반응값을 검토한 뒤 **최적화할 반응값** 하나와 모델·목표를 정합니다. 여러 반응을 함께 맞추려면 **여러 반응 만족도로 추천**에서 반응마다 목표(최대화·최소화·목표값)와 하한·목표값·상한을 적습니다. 반응마다 따로 모델을 맞춘 뒤 Derringer–Suich 종합 만족도 D가 가장 큰 조건을 찾습니다(`docs/DOE_MIXTURE.md`와 같은 계산). 실패·누락 행은 자동 제외하지 않습니다. 제외할 행 번호와 사유를 직접 입력해야 합니다. 계산 원본이 바뀌거나 단위·방법·분석 코드가 다르면 최적화를 거부합니다. 최신 버전으로 다시 분석한 뒤 사용하세요.
6. 추천 조건이 나오면 **별도 계산 1개 실행**을 눌러 확인 계산을 제출합니다. 완료 후 **확인 결과 분석·비교**로 예측값과 관측값 차이를 확인합니다. 만족도 추천이면 목표를 정한 반응마다 차이를 보여 줍니다. 이 값도 미검증 시뮬레이션 결과이며 검토된 실험 측정값으로 자동 등록하지 않습니다. 직접 진행할 때는 다음 단계나 다음 최적화 반복을 자동으로 시작하지 않습니다. 한 번에 맡기려면 아래의 승인한 계획 실행을 쓰세요.

### 승인한 계획으로 끝까지 실행

단계마다 누르는 대신, 계획을 한 번 승인하고 끝까지 맡길 수 있습니다. 흐름 화면의 **승인한 계획으로 끝까지 실행**을 엽니다.

1. 행마다 시도 횟수(1~3회), 허용 실패 행 수, 반응표면 최적화·확인 계산·보고서·Drive 업로드 여부를 정합니다. **최적화 방식**은 3단계에서 고른 반응값 하나(모델·목표 포함) 또는 위 만족도 표의 목표입니다. 행을 선택하면 그 행만, 선택하지 않으면 모든 행을 계획에 넣습니다.
2. **계획 미리보기**는 계산할 행, 계획 밖이라 최적화에서 제외할 행, **최대 계산 수**(행마다 남은 시도 + 확인 계산의 시도)와 남은 예산을 보여 줍니다.
3. **이 계획과 최대 N개 계산을 승인하고 실행**을 누르면 승인 시각·계획 해시·승인 예산이 기록되고 다음을 묻지 않고 진행합니다.
   - 계획한 행을 제출합니다. 실패하거나 서버 재시작으로 중단된 계산은 **같은 설정·같은 시드**로 시도 횟수까지 다시 제출합니다. 설정은 바꾸지 않습니다.
   - 엔진·입력 부족(blocked), 사람이 취소한 계산, 기록이 없는 계산은 재시도하지 않습니다. blocked는 곧바로 멈춥니다.
   - 실패한 행이 허용 수를 넘으면 멈춥니다. 허용 범위 안의 실패 행은 "자동 실행: 계산 실패 (2회 시도)" 같은 사유와 함께 최적화에서 제외합니다.
   - 완료된 행을 분석하고, 반응표면을 맞추고, 추천 조건의 확인 계산 1개를 실행해 예측과 비교한 뒤 보고서를 만듭니다.
4. 진행 상황은 흐름 화면에 단계별 기록으로 표시됩니다. 실행 중에는 같은 흐름의 단계를 직접 실행할 수 없습니다. **자동 실행 멈추기**는 현재 단계가 끝난 뒤 멈추며, 이미 실행 중인 계산은 계속됩니다. **이 흐름 실행 취소**는 자동 실행과 계산을 함께 취소합니다.

승인 예산은 미리보기의 최대 계산 수 이상이어야 하고 흐름의 남은 예산을 넘을 수 없습니다. 서버가 재시작되면 자동 실행은 "서버 재시작으로 멈춤"이 되고, 같은 계획을 다시 승인하면 남은 부분부터 이어 갑니다. 자동 실행이 만든 반응값·추천·확인 결과도 모두 검토 전 시뮬레이션입니다. MCP의 `run_research_workflow_plan`은 사용자가 대화에서 계획과 계산 수를 승인한 뒤에만 시작합니다.

**흐름 실행 취소**는 해당 흐름의 대기·실행 계산과 분석을 취소합니다. 실패·중단 행은 선택한 뒤 **재시도 미리보기**로 새 작업을 만들 수 있고 이전 기록은 남습니다. 서버를 재시작하면 진행 중 단계는 중단 상태로 표시하며 자동 재실행하지 않습니다. Linux에서는 서버가 비정상 종료되어도 계산 프로세스 그룹이 종료되도록 부모 종료 감시를 설정합니다.

실행 큐는 세 줄로 나뉩니다. **MD 계산**(작업), **구조·접촉 분석**(RDF·MSD·자유 부피·Widom·분자 접촉 χ), **통계 계산**(DOE 설계·분석)이 줄마다 한 번에 하나씩 순서대로 실행되며, 서로 다른 줄은 기다리지 않습니다. MD가 실행 중이면 분석 프로세스는 MD 몫(`POLYMER_MD_THREADS`, 기본 최대 4개)을 뺀 나머지 논리 코어만 쓰고, 남는 코어가 없어도 1개는 씁니다. 화면·MCP에서 직접 요청한 계산은 같은 줄이 30초 안에 비지 않으면 HTTP 429와 진행 중인 줄 이름을 돌려줍니다. 연구 흐름의 분석·최적화 단계는 취소할 수 있으므로 같은 줄이 빌 때까지 기다립니다. 줄 안의 순서는 Rust 큐가 정하며, Rust 확장이 없는 환경은 Python 대체 큐를 씁니다. 같은 기능의 중복 동시 호출은 기존과 같이 HTTP 429를 반환할 수 있고, 분석 프로세스의 1시간 실행 한도와 전체 대기열 상한(16개)도 적용됩니다.

흐름 연결 기록·변경 이력·최적화 결과는 `research/workflows/`에 저장되고 전체 ZIP/Drive 백업에 포함됩니다. 계산과 분석 원본은 기존 작업/분석 폴더에 별도로 보존합니다. 실행 중 계산은 기존 백업 정책에 따라 제외되므로 완료 후 새 백업을 만드세요.

## 고분자 계산 경로

**워크플로우**에서 목적에 맞는 경로를 선택합니다. 반복단위 SMILES의 연결 지점은 보통 두 개의 `[*]`로 표시합니다. `[*]CC[*]`는 단순한 연결 예제입니다. 연결점이 2개가 아니거나 벌크 셀 원자가 200개보다 적으면 작업을 만들기 전에 오류를 표시합니다. `C=Cc1ccccc1`(스티렌)처럼 단량체를 넣으면 이중결합 하나를 연 반복단위 후보(예: `[*]CC([*])c1ccccc1`)를 함께 보여줍니다. 후보는 1,2-부가만 가정한 것이므로 실제 중합 방식과 맞는지 확인한 뒤 쓰세요. 사슬 길이·말단·입체규칙성·전하·온도·압력을 연구 조건에 맞게 확인하세요.

| 경로 | 입력과 산출물 | 적합한 용도 |
|---|---|---|
| 조대화 고분자 | 비드 사슬 → LAMMPS 또는 NumPy 동역학 → 궤적·Rg | 사슬 거동의 정성 비교와 실행 연습 |
| 전원자 구조 생성 | 반복단위 → RDKit 연결·3D 배치·MMFF | 한 사슬 구조 준비 |
| 전원자 단일 사슬 MD | GAFF2_mod/Gasteiger → 최소화·짧은 NVT | 고립 사슬의 초기 거동 확인 |
| GAFF2 벌크 셀 | 여러 사슬 → 셀 생성·Larsen 21단계 → NPT | 주기 셀의 밀도·열역학 피처와 구조 분석 |
| PCFF 벌크 셀 | EMC의 PCFF 타입·전하·구조 → LAMMPS class2 | Class II 힘장의 벌크 셀 탐색 |
| 에폭시–아민 가교 | EMC 혼합물 → 반응 템플릿 → bond/react → 냉각 | 구조 전환율·네트워크와 경화 셀 탐색 |
| Tg 냉각 스캔 | 완료된 벌크·가교 셀 → 단계 냉각 NPT → 비부피 쌍곡선 맞춤 | 같은 냉각 속도에서 셀끼리 Tg·열팽창 비교 |
| pysimm | GAFF2/Gasteiger → 에너지 최소화 | 별도 엔진을 이용한 고립 사슬 최소화 |

GAFF2 벌크의 셀 빌더는 지원되는 자체 빌더 또는 RadonPy를 선택합니다. `xtb`가 설치된 경로에서는 CM5 전하를 사용할 수 있습니다. 엔진과 힘장을 바꾸면 같은 온도에서도 결과가 달라질 수 있으므로 비교할 때 방법을 함께 기록하세요.

조대화 기본 모델은 환산 단위의 soft 반발·harmonic 결합 모델입니다. 입력 SMILES에 맞춘 화학종별 보정이 아니며 비드의 통과를 허용합니다. NumPy overdamped 적분과 LAMMPS 관성 동역학의 시간 척도를 그대로 비교하지 않습니다.

벌크 계산은 시간 배율을 낮추면 빠르게 동작을 확인할 수 있지만 평형 물성을 얻기에는 부족할 수 있습니다. 특히 체적탄성률·열용량·압축률은 충분한 요동 샘플링이 필요합니다. 벌크·가교 작업 자체는 Tg를 계산하지 않습니다. Tg는 아래 **Tg 냉각 스캔**을 따로 실행합니다. 가교의 접촉 기반 반응은 구조 생성 모델이며 실제 경화 속도론을 나타내지 않습니다. **반응 거리 단계**를 "3.5 Å부터 0.5 Å씩 늘림"으로 두면 가까운 쌍부터 반응시키고, 목표 전환율에 이르면 남은 단계를 건너뜁니다. **2차 아민 반응 확률**은 1차 아민보다 느린 2차 아민 반응을 흉내 내는 가정값입니다. PCFF·가교 작업은 실행 전에 힘장 계수(0·빠짐·비정상 값)를 점검해 `coefficient_check.json`에 남기고, EMC에 계수가 없는 구조(예: PDMS)는 빠진 항목을 알려 주며 실패합니다. 이때는 GAFF2 벌크 셀을 쓰세요.

### Tg 냉각 스캔

완료된 벌크 셀이나 가교 작업을 열고 **이 셀로 Tg 냉각 스캔**을 누르면 전원자 경로의 "Tg 냉각 스캔" 방식으로 연결됩니다. 원본 작업의 최종 구조(GAFF2는 `eq3_last.data`, PCFF·가교는 `final.data`)와 힘장 설정을 복사해 다시 실행하므로 원본 작업은 바뀌지 않습니다.

1. 최고 온도에서 한 번 유지한 뒤, 최고 온도부터 최저 온도까지 온도 간격마다 1 atm NPT로 정해진 스텝만큼 유지합니다.
2. 각 온도의 뒤쪽 절반에서 평균 온도와 평균 비부피(1/밀도)를 구합니다.
3. 비부피–온도 점에 쌍곡선을 맞춰 두 점근선이 만나는 온도를 Tg로 보고합니다(Patrone 외, *Polymer* 87, 2016). 95% 구간은 프로파일 우도로 구하고, 두 직선 맞춤의 Tg와 잔차 부트스트랩 구간을 함께 보여 줍니다.
4. 저온 쪽과 고온 쪽 기울기로 체적 열팽창 계수를 계산합니다.

결과에는 냉각 속도(K/ns)가 항상 붙습니다. 기본값(20 K 간격, 온도당 200,000 스텝 = 200 ps)은 100 K/ns, 즉 10¹¹ K/s로 DSC(10 K/min)보다 약 6×10¹¹ 배 빠릅니다. 16온도 스캔이면 모두 3.4 ns를 계산하므로 1,300원자 셀도 4코어에서 몇 시간이 걸립니다. 그래서 MD Tg는 DSC보다 높게 나오는 것이 정상이고, 이 앱은 WLF 등으로 실험값을 환산하지 않습니다. 기울기 변화가 뚜렷하지 않거나 Tg가 스캔 끝에 걸리면 "전이 미확인"으로 표시합니다. 이때는 온도 범위를 넓히거나 온도당 스텝을 늘리세요. 한 셀의 한 번 스캔이라 구간은 셀 사이 차이를 담지 않습니다. 짧은 올리고머 셀은 사슬 말단 때문에 Tg가 낮아지므로 비슷한 사슬 길이끼리만 비교하세요. 1,296원자 PS 탐색용 셀을 온도당 50 ps로 스캔했을 때는 이웃 온도 사이 산포(약 1%)가 커서 전이가 확인되지 않았습니다(`docs/GLASS_TRANSITION.md`). 그래서 기본값을 200 ps로 늘렸습니다. 같은 셀을 200 ps로 다시 스캔하니 산포는 약 0.6%로 줄었지만, Tg 위 온도가 1개뿐이어서 여전히 전이가 확인되지 않았습니다. 600 K에서 시작해 보니 고무 쪽 산포(약 1.5%)가 커서 역시 확인되지 않았습니다. 1,300원자 정도의 셀 하나로는 부족하므로, 시작 온도를 Tg보다 충분히 높게 잡고 수천 원자 이상의 셀과 독립 복제 여러 개를 권합니다.

## 구조와 궤적 분석

완료된 전원자 **벌크 셀 또는 가교** 작업을 열면 지원되는 **구조·궤적 분석**이 표시됩니다. GAFF2 벌크의 `eq3_last.data`와 `eq3.dump`를 사용하며, PCFF·가교는 `final.data`의 최종 구조를 사용합니다. 지원하는 입력은 직교 주기 셀입니다. 분석은 원본 구조·궤적을 변경하지 않습니다.

방법을 선택하고 조건을 입력한 다음 **분석 실행**을 누릅니다. 설정을 바꿨다면 다시 실행해야 새 조건이 결과에 반영됩니다. 앱은 동시에 한 건의 구조 분석을 수행합니다. 프레임·격자·삽입 수가 크면 계산량 제한에 걸릴 수 있습니다.

### RDF

원자 간 거리의 분포 `g(r)`를 계산합니다. 원소 쌍은 `C-C; C-H`처럼 세미콜론으로 나누거나 `all-all`, `heavy-heavy`를 사용합니다. `all`은 전체 원자, `heavy`는 수소를 제외한 원자입니다. 같은 분자 내부의 쌍을 제외할지 선택할 수 있으며 자기 자신과의 쌍은 제외됩니다.

최대 거리는 선택한 프레임들에서 가장 짧은 상자 길이의 절반 이하여야 합니다. 거리 단위는 Å이며 `g(r)`는 무차원입니다. 최종 구조만 있으면 한 프레임 결과이므로 궤적 평균과 구분하세요.

### MSD

선택 원자의 평균 제곱 변위를 여러 시간 원점에 대해 계산합니다. `heavy`, `all`, `C,O` 같은 원자 선택을 사용합니다. 프레임이 일정한 시간 간격을 갖고 원자 식별자가 일관된 GAFF2 궤적이 필요합니다. 시간 간격을 비우면 원래 작업 설정의 MD 시간 간격을 사용합니다.

기본값은 전체 셀의 질량 중심 이동을 제거합니다. 주기 경계의 이미지 정보를 이용한 변위를 계산하며 시간 단위는 ps, MSD는 Å²입니다. 피팅 기울기가 양수이고 로그–로그 기울기가 0.9~1.1인 구간에서만 확산 계수 추정치를 표시합니다. 조건을 충족하지 않으면 값은 `null` 또는 **추정 불가**입니다. 이 판정만으로 평형이나 장시간 확산 수렴을 입증할 수는 없습니다.

### 자유 부피

최종 구조에 대해 탐침 반지름과 격자 간격 h를 지정합니다. 반지름은 Å 단위로 `0, 1, 1.5`처럼 입력합니다.

- **탐침 0 자유 부피:** 원자의 반데르발스 구 바깥 공간의 비율입니다.
- **접근 가능 부피:** 탐침의 중심이 들어갈 수 있는 공간입니다.
- **탐침 점유 부피:** 들어갈 수 있는 탐침들이 덮는 공간입니다.
- **Bondi FFV:** 반데르발스 점유 부피 Vw와 셀 부피 V로 계산한 `1−1.3Vw/V`입니다. 다른 정의의 자유 부피와 구분합니다.

h와 2h 격자의 결과·절대 차이·실제 축별 간격을 함께 확인합니다. 작은 격자가 더 많은 계산을 요구하며, 두 값의 차이는 오차 상한이나 수렴 증명이 아닙니다. 막힌 공동도 포함하므로 연결된 확산 통로나 투과성을 뜻하지 않습니다.

### Widom 기체 삽입

지원 기체는 He, H₂, N₂, O₂, Ar, CH₄, CO₂입니다. GAFF2 벌크 셀에서 기체·온도·프레임당 삽입 수·난수 시드를 정합니다. PCFF·가교 셀의 9–6 LJ에는 이 분석을 적용하지 않습니다. 궤적이 없으면 최종 구조 한 프레임을 사용합니다.

단일 점 Lennard–Jones 기체를 고정된 고분자 구조에 가상 삽입하여 과잉 화학 퍼텐셜과 용해도 계수를 추정합니다. 전하·사중극자·고분자 이완을 포함하지 않습니다. NPT 궤적은 프레임 부피로 가중한 삽입 평균을 사용합니다. 용해도 단위는 `cm³(STP)/(cm³·atm)`이며 표준 오차는 독립 프레임 가정에 근거합니다. 프레임 간 상관이나 힘장·모델 오차가 모두 반영되지는 않습니다.

삽입 횟수·독립 프레임·평형화 조건을 늘려 안정성을 확인하세요. 모든 삽입 가중치가 0이면 화학 퍼텐셜을 유한한 수치로 추정할 수 없습니다. 짧은 PS 셀의 기존 검증에서는 용해도를 실험보다 약 10배 크게 예측한 사례가 있어 절대값 사용에는 추가 검증이 필요합니다.

성공한 분석은 `research/analyses/<기록 ID>/result.json`에 별도 저장되어 전체 백업에 포함됩니다. **분석 JSON 저장**으로 조건·단위·경고·입력 SHA-256·커널과 분석 코드 정보를 함께 내려받을 수도 있습니다.

## 단백질과 혼합계

### 구조 가져오기와 표면 분석

**단백질 · AlphaFold / ColabFold**에서 다음 방법을 선택합니다.

| 방법 | 필요한 입력 | 얻는 결과 |
|---|---|---|
| AlphaFold DB | UniProt 접근 번호 | 공식 DB에 이미 존재하는 예측 구조 |
| 내 PDB | PDB 파일 | 구조·기하·표면 분석 |
| AF3 입력 내보내기 | 서열·입력 조건 | 다른 실행 환경에 전달할 입력 파일 |
| 로컬 ColabFold | 서열, 설치된 실행기·가중치·GPU 환경 | 환경이 준비된 경우 새 구조 추론 |

일반 PDB의 B-factor는 자동으로 pLDDT로 해석하지 않습니다. 사용자가 신뢰도 값임을 지정했는지 확인하세요. 낮은 신뢰도 영역이나 빠진 잔기가 중요한 결합 위치에 있다면 먼저 구조를 검토합니다. 필요한 경우 지원되는 PDBFixer 보정 경로를 사용하고 원래 구조와 비교합니다.

SAP는 정적 구조의 노출 소수성 패치를 찾는 지표입니다. MD 앙상블 평균이나 실제 응집 속도를 계산하는 것은 아닙니다. PROPKA는 지정 pH의 pKa·양성자화와 전하를 추정하고, PDB2PQR은 수소를 포함한 입력 구조를 만듭니다. 표시되는 Debye–Hückel 표면 전위는 패치 선별용이며 정밀한 APBS 정전기 계산과 구분합니다.

### 고분자와 함께 배치

1. 단백질 구조 작업을 먼저 완료하고 검토합니다.
2. PACKMOL 경로에서 그 작업을 고르고 고분자 반복단위·길이·개수를 정합니다.
3. 박스 전체, SAP 패치, 양·음전하 패치 중 배치 위치를 선택합니다. 전하 패치에 배치할 때 고분자 전하의 부호도 확인합니다.
4. 결과 구조를 3D 화면에서 확인합니다. PACKMOL 결과는 초기 배치이며 공통 힘장과 토폴로지가 자동 완성된 MD 결과가 아닙니다.

조대화 비드와 전원자 단백질을 같은 힘장으로 혼합했다고 해석하지 않습니다. polyply의 기본 Martini 3 PEO 경로는 분자 토폴로지를 준비하며, 좌표·전체 힘장·MDP와 GROMACS가 갖춰진 실행 단계와 구분합니다.

### 혼합계 MD

**혼합계 준비**의 Martini 3 경로에서는 검토한 단백질 PDB·2차 구조와 설치된 고분자 블록을 지정합니다. martinize2/polyply와 확인된 힘장을 사용해 물·이온을 포함한 계를 만들고 GROMACS로 최소화 → 위치 구속 NVT → 위치 구속 NPT → 짧은 생산 계산을 수행합니다.

두 가지 선택 옵션이 있습니다.

- **탄성망 pLDDT 하한**: 탄성 네트워크를 켜고 구조의 B-factor가 pLDDT임을 확인하면(AlphaFold 예측 구조), CA pLDDT가 하한 이상인 연속 3잔기 이상 구간 안에서만 탄성 결합을 만듭니다. 신뢰도가 낮은 구간(흔히 무질서 영역)은 묶지 않고, 서로 다른 신뢰 구간 사이도 묶지 않습니다. 단일 사슬만 지원하며, 쓰인 구간은 `elastic_regions.json`에 남습니다.
- **단백질–고분자 ε 배율 λ(실험적)**: Martini 3는 단백질과 고분자가 지나치게 뭉치는 경향이 알려져 있습니다. λ < 1이면 단백질 비드–고분자 비드 쌍의 LJ ε만 λ배로 줄입니다. 단백질끼리, 고분자끼리, 물·이온과의 상호작용은 그대로입니다. 이 계에 맞춰 정한 값이 아니므로 λ = 1 결과와 나란히 보고하세요. 바꾼 쌍과 파일 해시는 `lambda_scaling.json`에 남습니다.

RMSD·접촉 수·회전반경·밀도는 해당 궤적에서 얻은 관측값입니다. 단백질과 고분자의 결합 자유에너지나 충분한 평형 도달을 나타내지 않습니다. AMBER 준비 템플릿과 OpenFF 연동 명세는 실제 지원되는 실행 단계까지만 완료로 해석합니다.

## 실험 데이터와 물성 학습

### 측정값과 출처

**연구 데이터**에서 완료된 작업을 새로 색인하면 계산 피처를 비교할 수 있습니다. **실험 데이터**에는 실험·문헌 측정값을 별도로 등록합니다. 반복단위 또는 대상 구조, 물성 이름, 값, 단위, 방법, 출처와 조건을 함께 기록하세요.

CSV는 화면의 열 이름에 맞추며 대표적인 열은 `repeat_smiles,property,value,unit,method,source,origin`입니다. `origin`은 실험값이면 `experimental`, 문헌값이면 `literature`로 구분합니다. Tg의 K, 탄성률의 MPa, Kd의 nM처럼 정규화한 단위와 원래 값을 함께 보관합니다. 서로 다른 온도·방법·고분자 종류를 의미 없이 합치지 마세요.

자동 추출·에이전트 입력은 검토 전 초안입니다. 원본과 값을 대조한 뒤 사람이 검토한 것으로 표시합니다. 계산값이나 모델 추천값을 실험 측정값으로 바꿔 등록하지 않습니다.

### 곡선과 문헌 파일

| 입력 | 분석할 수 있는 항목 | 반드시 정할 조건 |
|---|---|---|
| DSC | Tg 기준점, Δcp, 용융 엔탈피·결정화도 | 온도·신호 단위, 기준선·적분 구간, 필요 시 기준 엔탈피 |
| TGA | 지정 질량 감소 온도, DTG 최대점, 개시 온도, 잔류량 | 질량 기준, 온도 범위·감소율 |
| GPC | Mn·Mw·Mz·분산도 | 표준 보정식, 기준선·적분 구간; 보편 보정에는 Mark–Houwink 상수 |
| 인장 | 지정 선형 구간의 탄성률 | 변형률·응력 단위와 선형 구간 |
| IR | 피크·작용기 후보, 지수·밴드 비·에폭시 전환율 | 스펙트럼 종류·기준 구간·참조 밴드 |
| UV-vis | λmax, Beer–Lambert 농도, 광학 밴드갭 | 흡광도/투과율 구분, 경로 길이·계수·피팅 구간 |
| 탁도 | LCST·UCST 흐림점 후보 | 온도 방향, 신호와 판정 조건 |

IR·UV-vis는 지원되는 JCAMP-DX 파일을 읽을 수 있습니다. GPC는 보정 표준에 대한 상대 분자량이며 모든 시료의 절대 분자량을 보장하지 않습니다. 자동 기준선을 썼더라도 원래 곡선과 피팅 구간을 확인하세요. PDF는 페이지별 텍스트와 해시를 보관하며 이미지의 OCR이나 LLM 자동 추출은 제공하지 않습니다.

### 물성 모델

**물성 학습 · 예측**에서는 사람이 검토한 실험·문헌 데이터로 가우스 과정(GP) 기준 모델을 학습합니다. 서로 다른 고분자 반복단위가 최소 8종 필요합니다. 목표 물성·조건·단위·데이터 수를 확인한 뒤 실행하세요.

구조 그룹을 나눠 교차 검증하며 가까운 참조 구조와 적용 범위를 표시합니다. 짧은 MD 피처를 결합할 수 있지만 이것만으로 다중 충실도 모델이나 고정밀 실험 예측이 되지는 않습니다. 표시된 불확실성은 별도로 보정되지 않았을 수 있으므로 새로운 계열의 고분자는 확인 실험이 필요합니다.

## 빠른 예측과 탐색 캠페인

### 빠른 예측과 상용성

**빠른 예측 · 상용성**은 긴 시뮬레이션 전에 후보를 줄이는 용도입니다.

- **PI1070 기반 예측:** 공개된 300 K MD 데이터 1,077종에서 학습한 모델로 밀도·열적 물성 등을 예측합니다. 가까운 참조 고분자와 적용 범위를 확인하세요. 목표값은 해당 MD 워크플로우의 결과이며 실험값이 아닙니다.
- **Hansen 상용성:** 용매·혼합물의 거리 Ra, RED, χ 등을 계산하고 입력한 용해 실험으로 구를 적합합니다. 온도·조성·분자량이 달라지면 실제 용해 거동도 달라질 수 있습니다.
- **Blends χ:** 공개 Fan 방법에 기반한 접촉 샘플링으로 χ(T)를 추정합니다. 일부 PS–지방족 용매에서 부호가 맞지 않는 검증 사례가 있습니다. 실험적 선별값으로 취급하고 절대 혼화성 판정에 단독 사용하지 마세요.

### 탐색 캠페인

명시한 유한 후보 목록, 목표 피처, 계산 예산과 배치 크기로 캠페인을 만듭니다. 예산은 최대 50개입니다. 사용자가 시작한 뒤 초기에는 다양한 후보를 고르고, 관측값이 5개 이상이면 GP/BayBE를 이용한 추천을 수행합니다.

앱 재시작 후 캠페인은 일시 정지되므로 상태를 확인하고 재개하세요. 계산 캠페인의 관측값은 해당 계산 경로의 결과입니다. 자동 계산이 실험을 대신 수행하거나 새 실험 사실을 만들어내지는 않습니다.

## 저장과 Google Drive 백업

### 로컬 저장 위치

| 실행 방식 | 계산 작업 | 연구 데이터 |
|---|---|---|
| 소스의 웹 앱 | 저장소의 `data/jobs/` | `data/research/` |
| 데스크톱 기본값 | `~/.local/share/polymer-lab/jobs/` | `~/.local/share/polymer-lab/research/` |

`POLYMER_DATA_DIR`을 지정하면 그 경로가 작업 폴더가 되고, 연구 데이터는 그 옆 `research` 폴더에 저장됩니다. 데스크톱 전체 데이터 위치는 `POLYMER_APP_DATA_DIR` 또는 `XDG_DATA_HOME` 설정의 영향을 받을 수 있습니다. 데스크톱의 데이터 폴더 메뉴로 실제 위치를 확인하세요.

DOE 기록은 `research/doe/<기록 ID>/`에 원본/설계 CSV와 결과 JSON으로, 구조 분석은 `research/analyses/<기록 ID>/`에 저장됩니다. 연구 데이터베이스는 실행 중인 DuckDB 파일을 직접 복사하는 대신 **스냅샷 만들기**로 일관된 Parquet 사본을 내보냅니다. 기존 동기화 폴더 설정은 이 사본을 지정한 로컬 폴더로 복사합니다. 폴더 복사만으로 Drive 업로드를 확인한 것은 아닙니다.

### 연구 보고서

저장된 기록 하나를 사람이 읽고 공유할 수 있는 보고서 폴더로 만듭니다. 보고서는 기록의 숫자와 검토 표시(`verified`, `validated`)를 그대로 옮길 뿐, 모델을 다시 맞추거나 값을 검토하지 않습니다.

| 만드는 곳 | 대상 | 들어가는 내용 |
|---|---|---|
| 실험 설계·최적화의 각 결과 아래 **보고서 만들기** | 설계, 반응표면 분석, 혼합물 분석, 만족도 최적화 기록 | 모델 요약, 계수·분산분석·모델 비교·행별 진단, 추천 조건과 구간, 입력 CSV. 관측값–적합값, 잔차, 파레토, 반응표면 등고선, 인자별 프로파일, 3성분 삼각 등고선, 반응별 만족도 그림 |
| 단계별 연구 흐름의 **보고서 만들기** | 벌크 연구 흐름 | 설계 행·작업·상태·반응값(모두 검토 전), 마지막 반응표면 분석, 확인 계산과 예측구간 비교, 연결된 측정값 기록 |
| 연구 데이터의 **마스터 표 보고서 만들기** | 전체 계산 기록과 측정값 | 한 시점의 스냅샷에서 읽은 계산 기록·측정값 표. 물성·출처 종류(실험·문헌·시뮬레이션·데모)·검토 여부별 개수와 학습에 쓸 수 있는 값의 수 |

보고서는 `research/reports/<보고서 ID>/`에 저장되며 이후 바뀌지 않습니다. 폴더에는 `summary.md`(한 쪽 요약), `report.html`(그림이 들어 있는 보고서), `figures/`(SVG와 PNG), `tables/`(CSV와 모든 표를 시트로 담은 `report.xlsx`), `manifest.json`(파일별 크기·SHA-256·MD5와 출처 기록의 해시)이 들어 있습니다. **보고서 보기**는 새 창에서 HTML을, **보고서 ZIP**은 폴더 전체를 내려받습니다.

- CSV는 엑셀에서 한글이 깨지지 않도록 UTF-8 BOM을 붙입니다. `=`, `+`, `-`, `@`로 시작하는 글자는 수식으로 실행되지 않도록 앞에 `'`를 붙입니다. 숫자는 저장된 값을 반올림 없이 씁니다.
- SVG는 글자를 글자 그대로 두므로 보는 컴퓨터의 한글 글꼴로 표시됩니다. PNG는 설치된 한글 글꼴(Noto Sans CJK KR, 나눔고딕, 맑은 고딕 등)로 그리며, 글꼴이 없으면 보고서 경고에 적습니다.
- **Drive에 올리기**는 아래의 본인 Drive 원격에서 `PolymerLab-reports/<날짜-종류-ID>/` 폴더로 파일을 복사합니다. 모든 파일의 크기와 MD5가 Drive 쪽과 같을 때만 "Drive 확인됨"으로 표시합니다. 만든 뒤 로컬 파일이 바뀌었으면 올리지 않습니다.

### 내 Google Drive 연결

앱의 **Google Drive에 저장**은 사용자가 rclone에 연결한 Google Drive 원격을 사용합니다. 클라우드 개발 환경의 공용 서비스 계정이나 GitHub의 백업 토큰을 개인 Drive 로그인으로 자동 사용하지 않습니다. 사용자 원격이 없으면 `setup_required`가 표시되며 처음 한 번 본인 계정 연결이 필요합니다.

1. 앱을 실행하는 컴퓨터에 [rclone](https://rclone.org/downloads/)을 설치합니다.
2. 터미널에서 `rclone config`를 실행하고 새 원격 이름을 예를 들어 `gdrive`로 만듭니다. 저장소 종류로 Google Drive를 고르고 본인 계정으로 브라우저 인증합니다. 본인 Google OAuth 데스크톱 클라이언트 사용을 권장하며, [Google Cloud](https://console.cloud.google.com/)에서 프로젝트 생성 → Drive API 활성화 → OAuth 동의 화면 설정 → 데스크톱 앱 클라이언트 생성 순으로 준비합니다. `drive.file` 범위는 rclone이 만든 파일만 다루는 백업 용도에 적합합니다.
3. rclone 설정 파일은 저장소·작업 데이터 폴더 밖의 사용자 보안 설정 위치에 둡니다. 앱이 다른 설정 파일을 사용해야 한다면 `RCLONE_CONFIG`에 그 파일 경로를 지정합니다. 원격 컴퓨터 인증은 rclone이 안내하는 브라우저 인증 절차를 따르세요.
4. 원격 이름만 환경 변수에 지정하고 앱을 실행합니다. 이름에 콜론이나 Drive 폴더 경로를 붙이지 않습니다.

```sh
POLYMER_DRIVE_REMOTE=gdrive ./start.sh
```

소스 데스크톱은 `POLYMER_DRIVE_REMOTE=gdrive ./launch-desktop.sh`로 같은 설정을 전달합니다. 메뉴에서 실행할 때도 앱 프로세스에 이 환경 변수가 전달되어야 합니다.

토큰·OAuth 비밀 값은 채팅에 보내거나 저장소에 커밋하지 마세요. 앱에는 원격 이름만 전달합니다. `설정됨` 표시는 로컬 원격 이름·종류를 확인한 것으로, 실제 로그인·통신 성공은 업로드할 때 확인합니다.

### 소스와 설명서와 연구 결과 저장

앱 상단의 **Google Drive에 저장 → 전체 백업 저장**을 누릅니다. 한 ZIP에 다음 내용을 묶습니다.

- 현재 소스와 설명서: 추적 중인 파일과 허용된 새 소스·문서 파일.
- 종료된 계산 작업의 입력·결과·로그·구조·궤적: 성공 외에도 준비·실패·차단·취소·중단 기록 포함.
- 일관된 Parquet 연구 데이터 스냅샷과 저장된 연구 자료·모델·캠페인 기록.
- DOE 설계·분석 JSON과 원본/설계 CSV, 저장된 RDF·MSD·자유 부피·Widom 분석 JSON.
- 파일 목록과 SHA-256 해시를 담은 백업 명세.

진행 중인 작업, 저장하지 않은 입력, 인증 설정, `.env`·토큰, 가상 환경·캐시·Git 이력, 심볼릭 링크와 이전 백업 ZIP은 제외합니다. 현재 실행 중인 계산까지 보관하려면 완료 후 새 백업을 만드세요. 원본 합계 4 GiB 또는 50,000개 파일을 넘으면 전체 백업을 중단하므로 큰 궤적은 개별 작업 ZIP 등으로 따로 보관해야 합니다. 내려받은 외부 엔진·의존성 전체를 함께 보관하는 환경 이미지가 아닙니다.

**전체 백업은 소스를 안전하게 열거할 수 있는 Git 체크아웃에서 실행해야 합니다.** Git 소스가 없는 독립 데스크톱 배포본에서는 소스 누락 백업을 만들지 않고 오류를 표시합니다. 이 경우 소스 환경에서 같은 작업 폴더를 지정해 백업하거나, 배포본에서 개별 작업 ZIP·연구 스냅샷을 저장합니다.

기본 저장 위치는 `gdrive:PolymerLab-backups/results/PolymerLab-results-<UTC 시각>-<고유 ID>.zip`입니다. 앱 백업은 매번 새 파일을 만들며 기존 Drive 파일을 덮어쓰거나 지우지 않습니다. 업로드 뒤 원격 파일의 크기와 MD5가 로컬 ZIP과 일치하는지 확인한 경우에만 검증된 업로드로 표시합니다. 로그인·통신·검증이 실패하면 실패 상태를 확인하고 제공되는 로컬 ZIP을 저장하세요. 로컬 ZIP이 생겼다는 사실만으로 업로드가 완료되지는 않습니다.

Drive 연결 전에도 **전체 백업 ZIP 받기**로 같은 내용의 로컬 ZIP을 만들 수 있습니다. 이 동작은 인터넷 업로드를 수행하지 않습니다. ZIP은 데이터와 소스의 보관용입니다. 원래 폴더와 분리한 위치에 풀어 명세와 파일을 확인하세요. 실행 환경·외부 엔진·로그인 설정까지 자동 복원하는 기능은 제공하지 않습니다. 실행 중인 앱의 데이터 위에 바로 덮어쓰지 마세요.

### GitHub의 소스 자동 백업

기존 `drive-backup` GitHub Actions는 `main`에 올라간 커밋 또는 수동 실행 시 `git archive`로 **커밋된 소스와 설명서**를 백업합니다. 로컬 연구 데이터와 커밋하지 않은 변경은 앱의 전체 백업으로 보관합니다.

GitHub 저장소의 **Settings → Secrets and variables → Actions**에 `RCLONE_DRIVE_TOKEN`을 설정합니다. 본인 OAuth 클라이언트를 쓰면 `DRIVE_CLIENT_ID`, `DRIVE_CLIENT_SECRET`도 Secrets에 둡니다. 토큰은 신뢰하는 컴퓨터에서 rclone의 `drive.file` 인증 절차로 얻어 Secrets에 직접 저장합니다. 본인 OAuth 동의 화면을 테스트 상태로 유지하면 갱신 토큰이 짧은 기간 후 만료될 수 있으므로 Google 설정을 확인하세요.

**Actions → drive-backup → Run workflow**에서 실행 결과를 확인합니다. 기본 파일은 `PolymerLab-backups/polymer-workbench-<커밋 시각>-<짧은 SHA>.zip`이며 `polymer-workbench-latest.zip`은 최신 커밋으로 갱신됩니다. 이 Actions의 `latest` 갱신은 앱의 매번 새로운 전체 백업과 다릅니다. 선택 변수 `DRIVE_BACKUP_FOLDER`로 폴더를 바꿀 수 있고, `DRIVE_BACKUP_KEEP_DAYS`를 설정한 경우에만 오래된 날짜별 소스 백업을 휴지통으로 이동합니다.

## 에이전트 연결과 REA

### MCP로 작업하기

Claude Code·Claude Desktop·Codex 같은 MCP 클라이언트에서 로컬 앱의 계산·분석을 호출할 수 있습니다. 앱을 먼저 실행하고 클라이언트의 MCP 서버 명령에 저장소의 Python 절대 경로와 인자를 등록합니다.

```sh
.venv/bin/python -m workbench --mcp
```

데스크톱 배포본은 `~/.local/bin/polymer-lab --mcp`를 사용합니다. 소스 저장소에는 `.mcp.json` 설정이 있습니다. 실행 중인 앱이 없으면 MCP가 세션 소유 서버를 만들 수 있지만, MCP 종료 시 그 서버도 종료되므로 긴 계산은 앱을 먼저 열어 두세요.

구조 분석 도구는 `analyze_job_structure`, DOE 도구는 `create_experiment_design`, `analyze_response_surface`입니다. 구조 분석과 DOE 도구는 결과 기록을 저장합니다. 에이전트가 입력한 측정값은 항상 검토 전 상태이며 사람이 확인해야 학습 데이터로 사용할 수 있습니다.

웹·모바일 클라이언트에 원격 연결하려면 `--mcp-http`와 HTTPS 터널을 별도로 구성합니다. 경로에 비밀 토큰이 들어 있는 연결 주소를 클라이언트에 직접 등록하고 공개 문서·로그·채팅에 올리지 마세요. 토큰이 노출되면 해당 서버의 `--new-token`으로 재발급합니다. 로컬 API의 개발용 명세는 앱의 `/docs`에 있습니다.

### Rust와 REA의 역할

Rust는 접촉 샘플링·구조/궤적 분석·DOE의 수치 계산을 담당합니다. REA는 공개 소스와 실제 빌드 산출물의 구조·메타데이터·출처를 조사하는 개발 감사 도구입니다. REA 감사가 계산 정확성이나 특정 상용 제품과의 동등성을 인증하지는 않습니다.

**REA 분석 근거**에서 제공하는 고정 커밋·파일 해시·원본 출력을 확인할 수 있습니다. 실제 설치된 Rust 바이너리 감사 기록은 `evidence/native/`에 있습니다. 개발자가 같은 감사를 다시 실행하려면 지원되는 Node.js와 `objdump`를 설치한 뒤 다음을 사용합니다.

```sh
python3 tools/rea/bootstrap.py
.venv/bin/python scripts/audit_native_artifact.py
```

외부 오픈소스의 감사 재생성은 `python3 scripts/audit_repos.py --refresh-sources --run-rea`입니다. 버전과 출처를 고정한 개발 검증 기록은 저장소에 유지하며, 사용자는 이 설명서의 실행 절차를 따르면 됩니다.

## 결과를 판단하는 기준

1. **방법과 단위를 함께 확인합니다.** 구조 생성, 초기 배치, 짧은 MD, 충분히 샘플링한 물성, 실험 측정, 대리 모델 예측을 구분합니다.
2. **하나의 성공 상태보다 수렴을 봅니다.** 계산 길이·셀 크기·독립 시드·격자·삽입 수를 바꿔 결과가 안정되는지 확인합니다. 두 설정의 차이만으로 오차 상한을 주장하지 않습니다.
3. **추천은 확인 실험으로 검증합니다.** DOE의 최적 조건과 물성 모델의 예측은 지정 범위와 입력 데이터의 한계 안에서 사용합니다.
4. **원본과 출처를 보관합니다.** CSV·구조·궤적·조건·코드/입력 해시·경고를 결과와 함께 저장하고 Drive 업로드 검증 여부를 확인합니다.
5. **공개 검증의 실패도 고려합니다.** Blends의 일부 부호 오류, 짧은 셀 Widom의 과대 추정 같은 알려진 한계를 무시하지 않습니다. 새 시스템에서는 독립 구현·문헌·실험과 다시 대조합니다.

## 수치 검증 기록

2026-10-23 개발 검증에서는 DOE의 공개 최소제곱 회귀 방법을 독립 구현과 대조했습니다. `tests/test_doe.py`는 합성 함수의 알려진 계수·최적점, NumPy 최소제곱 해·공분산과 SciPy의 추론 값을 확인합니다. `tests/test_doe_api.py`는 설계 CSV → 반응값 입력 → 실제 Rust 분석 → 저장·다운로드 흐름을 검증합니다.

- 분석해가 있는 함수 `10−(u−0.25)²−2(v+0.5)²`에서 인자 범위가 온도 −2~2, 압력 10~14일 때 물리 단위 최적 조건 `(0.5, 11)`, 예측값 10을 재현했습니다. u와 v는 −1~1로 환산한 인자입니다.
- 별도로 생성한 2~6인자, 주효과·상호작용·2차 모델의 추정 가능한 무작위 문제 130개에서 Rust QR 회귀와 NumPy 최소제곱을 비교했습니다. 계수의 최대 절대 차이는 `1.64×10⁻¹⁴`, 표준 오차는 `4.86×10⁻¹⁷`이었습니다. `OPENBLAS_NUM_THREADS=1 .venv/bin/python scripts/validate_doe_numerics.py`로 재현할 수 있습니다. 검증에 사용한 범위의 수치 일치이며 모든 입력에 대한 오차 상한은 아닙니다.
- 구조 분석의 합성 경계 조건과 MDAnalysis 대조는 `tests/test_structure_analysis.py`, Python–Rust 입력 검증은 `tests/test_native_bindings.py`에서 확인합니다. 실제 고분자 셀의 물리적 타당성은 합성 회귀 테스트와 별도로 판단합니다.

공정 데이터 분석은 [공정 데이터 검증 기록](PROCESS.md)에 있습니다. 분산 성분 제곱합과 Mantel–Haenszel·CMH·Breslow–Day 값은 statsmodels 0.14.5와 무작위 40개 사례에서 차이 10⁻¹¹ 이하로 일치했습니다. NIST/SEMATECH 핸드북 Furnace 사례(회차 312.56, 구역 225.38, 웨이퍼 120.89)와의 대조는 `scripts/validate_process_furnace.py`로 NIST에 접속할 수 있는 PC에서 실행합니다. 불량 판정 지표·순위 지표·최소 비용 기준은 scikit-learn과 무작위 200개 사례에서 차이 10⁻¹⁵ 이하로 일치했고, SECOM 공개 데이터 대조는 `scripts/validate_secom.py`로 실행합니다.
